SIM_TURRET_INTEGRATION - How to wire the sim into the real robot

Overview
--------
This project contains a lightweight offline simulation for the robot pose and turret:
 - src/main/java/frc/robot/turret/TurretPhysicsSim.java  (physics model)
 - src/main/java/frc/robot/turret/TurretSubsystemSim.java (simulated subsystem wrapper)
 - src/main/java/frc/robot/sim/RobotTurretSimRunner.java (runner that integrates robot pose, turret sim, and target)

Goal
----
Make it easy to replace the simulated turret with the real hardware implementation when the bot is available. Follow these steps to integrate.

Steps to integrate into the real robot
-------------------------------------
1. Replace the turret backing class:
   - The real robot should provide an implementation that offers the same public API as TurretSubsystemSim:
     - setTargetAngle(Rotation2d)
     - getAngle(): Rotation2d
     - atSetpoint(): boolean
     - update(double dtSeconds) // optional for simulators, NOP for hardware
     - reset(angleRad, angularVelocity)
   - Implement these methods using your motor controllers, encoders, and feedforward/closed-loop control.

    - We added a TurretSubsystemIO interface and updated RobotContainer to switch between
       TurretSubsystemSim and TurretSubsystem at runtime using RobotBase.isSimulation().

2. Add a factory or runtime switch:
   - In RobotContainer or your initialization code, create the real subsystem for the hardware robot and the simulated one for offline tests. Example:
     TurretInterface turret = isSimulation() ? new TurretSubsystemSim() : new TurretSubsystemHardware();

3. Use TargetEstimator and SwervePoseEstimator as-is:
   - The simulation writes the true hub pose into TargetEstimator. For the real robot wire your vision pipeline (LimelightHelpers or other) to call TargetEstimator.addObservation(pose, timestamp) when new vision poses are available.

4. Mapping sim helpers to real classes
    - The sim includes two small helper classes: SimPoseEstimator and SimRangeEstimator.
       These are intentionally trivial and expose a compatible surface that you can swap with your
       real `SwervePoseEstimator` and whatever range estimator you use.
    - To replace:
          - Use your real SwervePoseEstimator in place of SimPoseEstimator.
          - Replace SimRangeEstimator with your vision/range pipeline or LimelightHelpers.getRobotPose_FieldSpace() distance.

5. Outputs and dashboard
    - The sim writes the following files to the repo root (overwritten each sim tick):
          - sim_output_pose3d.txt (full tick dump)
          - sim_latest_pose3d.txt (latest tick only, useful for dashboards)
    - Each file contains:
          - robot Pose3d (field frame)
          - turret Pose3d (field frame)
          - relative vector to hub (dx, dy, distance, relative angle in robot frame)
          - target velocity estimate from TargetEstimator (vx, vy)
          - poseEstimator output (Pose2d)
          - rangeEstimator output (meters)
   - NetworkTables output (live):
        - /Sim/Turret/robotPose
        - /Sim/Turret/turretPose
        - /Sim/Turret/relX, relY, relDist, relAngleRobot
        - /Sim/Turret/targetVelX, targetVelY

6. Publish Pose3d to your preferred IO channel:
   - The simulation writes the robot and turret Pose3d to sim_output_pose3d.txt. For the real robot publish the same Pose3d to NetworkTables or your logger so the UI/driver station can display it.

7. Tuning parameters:
   - Tune motor constants, gear ratio, inertia, and friction in TurretPhysicsSim for closer offline matching.

8. Hybrid camera data (record + replay) for real-world measurement
   - Use VisionTelemetryRecorder to capture real camera measurements and replay them in sim.
   - Record mode:
      - In RobotTurretSimRunner, set recordVision=true in sim_inputs.txt (see input format below).
      - During simulation, the sim writes camera pose data to sim_vision_recording.csv.
      - For real robot logging, use your camera pipeline to call:
          VisionTelemetryRecorder recorder = new VisionTelemetryRecorder("sim_vision_recording.csv");
          recorder.record(estimatedTargetPose, Timer.getFPGATimestamp());
      - This produces a CSV file with timestamp,x,y,deg entries.
   - Replay mode:
      - Set replayVision=true in sim_inputs.txt to load the recorded CSV and feed it into TargetEstimator.
      - This lets you combine real sensor data with the physics sim ("hybrid" mode).
   - Notes:
      - If no replay data is found, the sim falls back to perfect hub pose observations.
      - You can re-use the same recorder on the robot for actual matches by writing to a new file name per run.

9. Geometry constants
   - SimGeometryConstants defines:
      - Field length/width
      - Hub poses
      - Turret offset (XY) and turret height
      - Camera-to-robot transform
      - Projectile speed
   - Tune these values to match your actual robot geometry.

Files to check/modify
---------------------
- src/main/java/frc/robot/turret/TurretSubsystemSim.java
- src/main/java/frc/robot/turret/TurretPhysicsSim.java
- src/main/java/frc/robot/sim/RobotTurretSimRunner.java

Simulation input/output files
----------------------------
- sim_inputs.txt  (repo root) — single-line file with:
      forward_m_s strafe_m_s omega_rad_s alliance recordVision replayVision
   Example: "1.0 0.0 0.0 blue true false"
- sim_vision_recording.csv — CSV recording of camera pose measurements (timestamp,x,y,deg)
- sim_output_pose3d.txt (repo root) — overwritten each tick with a human-readable dump of the robot Pose3d, turret Pose3d,
   the relative vector to the hub (dx,dy,distance,relative angle in robot frame), and the TargetEstimator's estimated
   velocity (vx,vy) in field coordinates.
- sim_latest_pose3d.txt — same as sim_output_pose3d.txt but always contains the most recent tick (handy for dashboards)

Notes
-----
- The sim is designed to be low-risk and easy to read. It is not a replacement for WPILib Simulator integration but is lightweight and easy to run on your machine.
- If you'd like, I can prepare a follow-up PR that wires TurretSubsystemSim behind a config flag so no code changes are necessary to switch between sim and hardware.
